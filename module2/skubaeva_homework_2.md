# Домашнє завдання №2
## Транспортний рівень та служби мережі

### Завдання 1. Аналіз відкритих портів
**Команда:**

`ss -tuln`

**Результати виконання:**

| Протокол | Порт | Стан | Призначення |
|---|---|---|---|
| TCP | 22 | LISTEN | SSH |
| TCP | 631 | LISTEN | CUPS |
| TCP | 53 | LISTEN | DNS |
| UDP | 53 | UNCONN | DNS |
| UDP | 5353 | UNCONN | mDNS |

**Пояснення:**

Команда `ss -tuln` показує TCP- та UDP-сокети, які очікують на з'єднання або отримання даних.

Порт 22 використовується для SSH, порт 631 — для служби друку CUPS, порт 53 — для DNS, а порт 5353 — для mDNS.

Стан `LISTEN` означає, що TCP-сокет очікує на вхідні з'єднання. Стан `UNCONN` характерний для UDP, оскільки цей протокол працює без встановлення з'єднання.

### Завдання 2. Аналіз процесів, що слухають порти

**Команда:**

`sudo ss -tulpn`

**Результати виконання:**

| Процес | PID | Порт |
|---|---|---|
| systemd-resolved | 606 | 53 |
| systemd | 1 | 22 |
| cupsd | 1557 | 631 |

**Пояснення:**

Команда `sudo ss -tulpn` дозволяє визначити процеси, які використовують мережеві порти.

- `systemd-resolved` — служба обробки DNS-запитів.
- `systemd` — системний менеджер, який у цьому випадку слухає порт 22 через механізм активації сокетів.
- `cupsd` — служба керування друком.

PID — це ідентифікатор процесу в операційній системі Linux.

Використання `sudo` дозволяє переглядати інформацію про системні процеси, яка може бути недоступною звичайному користувачу.

### Завдання 3. Перевірка TCP-з'єднання

**Команда:**

`nc -vz -w 5 google.com 80`

**Результат виконання:**

```text
Connection to google.com (142.250.120.101) 80 port [tcp/http] succeeded!
```

**Аналіз:**

- Тип з'єднання: TCP.
- Порт: 80 (HTTP).
- IP-адреса сервера: `142.250.120.101`.
- Результат: з'єднання успішно встановлено.

**Пояснення:**

Команда `nc -vz` перевіряє можливість встановлення TCP-з'єднання з віддаленим сервером.

Порт 80 зазвичай використовується для HTTP. Повідомлення `succeeded!` підтверджує, що TCP-з'єднання із сервером Google успішно встановлено.

Параметр `-w 5` обмежує час очікування до 5 секунд.

### Завдання 4. Порівняння TCP та UDP

**Команда 1 — перевірка UDP:**

`nc -u -vz -w 3 8.8.8.8 53`

**Результат:**

```text
Connection to 8.8.8.8 53 port [udp/domain] succeeded!
```

**Команда 2 — перевірка TCP:**

`nc -vz -w 3 8.8.8.8 53`

**Результат:**

```text
Connection to 8.8.8.8 53 port [tcp/domain] succeeded!
```

**Порівняння результатів:**

| Параметр | TCP | UDP |
|---|---|---|
| Порт | 53 | 53 |
| Результат команди | succeeded | succeeded |
| Встановлення з'єднання | Так | Ні |
| Надійна доставка на рівні протоколу | Так | Ні |

**Пояснення:**

Обидві команди вивели повідомлення `succeeded!`, але поведінка протоколів відрізняється.

TCP встановлює з'єднання перед передаванням даних. Успішний результат підтверджує встановлення TCP-з'єднання з портом 53.

UDP працює без встановлення з'єднання. Тому повідомлення `succeeded!` не гарантує, що віддалений сервер отримав пакет або надіслав відповідь.

**Висновок:**

TCP забезпечує надійне передавання даних із підтвердженням доставки та контролем порядку пакетів. UDP передає датаграми без встановлення з'єднання і не гарантує доставку.

Отже, хоча обидві перевірки завершилися успішно, для TCP результат підтверджує встановлення з'єднання, а для UDP — не підтверджує отримання відповіді від сервера.

### Завдання 5. DNS-резолвінг

**Команда:**

`nslookup github.com`

**Результат виконання:**

```text
Server:         127.0.0.53
Address:        127.0.0.53#53

Non-authoritative answer:
Name:   github.com
Address: 140.82.121.4
```

**Визначені параметри:**

- Домен: `github.com`.
- IP-адреса домену: `140.82.121.4`.
- DNS-сервер: `127.0.0.53`.
- Порт DNS-сервера: 53.

**Пояснення:**
Команда `nslookup` використовується для визначення IP-адреси доменного імені за допомогою DNS.
У результаті виконання команди домен `github.com` було перетворено на IP-адресу `140.82.121.4`.
DNS-запит обробив локальний DNS-резолвер `127.0.0.53`, який працює через службу `systemd-resolved`. Ця служба може звертатися до зовнішніх DNS-серверів для отримання інформації.
Позначка `Non-authoritative answer` означає, що відповідь надана не безпосередньо авторитетним DNS-сервером домену.

**Висновок:**
DNS дозволяє визначати IP-адреси сайтів за їхніми доменними іменами. Завдяки цьому користувачам не потрібно запам'ятовувати числові IP-адреси.

### Загальний висновок
Під час виконання домашнього завдання було досліджено відкриті мережеві порти Linux, визначено процеси та їхні PID, перевірено TCP-з'єднання і порівняно роботу протоколів TCP та UDP.
Також було виконано DNS-резолвінг для домену `github.com` та визначено його IP-адресу й локальний DNS-сервер.
Практична робота допомогла краще зрозуміти принципи роботи транспортного рівня, мережевих портів і служб DNS.
