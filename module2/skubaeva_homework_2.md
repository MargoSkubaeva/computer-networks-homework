# Домашнє завдання №2
## Транспортний рівень та служби мережі

### Завдання 1. Аналіз відкритих портів (2 бали)

**Команда:**

`ss -tuln`

**Результат виконання:**

```text
[Вставити результат команди ss -tuln]
```

**Виявлені відкриті порти:**

| Протокол | Порт | Стан |
|---|---|---|
| [TCP/UDP] | [порт 1] | [LISTEN/UNCONN] |
| [TCP/UDP] | [порт 2] | [LISTEN/UNCONN] |
| [TCP/UDP] | [порт 3] | [LISTEN/UNCONN] |

**Пояснення:**

Команда `ss -tuln` показує TCP- та UDP-сокети, які очікують на мережевий трафік. TCP-сокети, що приймають підключення, мають стан `LISTEN`. Для UDP зазвичай відображається `UNCONN`, оскільки цей протокол не встановлює з'єднання перед передаванням даних.

### Завдання 2. Аналіз процесів, що слухають порти (2 бали)

**Команда:**

`sudo ss -tulpn`

**Результат виконання:**

```text
[Вставити результат команди sudo ss -tulpn]
```

**Виявлені процеси:**

| Процес | PID | Порт |
|---|---|---|
| [назва процесу 1] | [PID] | [порт] |
| [назва процесу 2] | [PID] | [порт] |
| [назва процесу 3] | [PID] | [порт] |

**Пояснення:**

Команда `ss -tulpn` дозволяє визначити процеси, які використовують мережеві порти. Параметр `-p` показує інформацію про процес, а `-n` відображає числові значення портів. PID — це унікальний ідентифікатор процесу в операційній системі. Використання `sudo` дозволяє побачити додаткову інформацію про системні процеси.

### Завдання 3. Перевірка TCP-з'єднання (2 бали)

**Команда:**

`nc -vz google.com 80`

**Результат виконання:**

```text
[Вставити результат команди]
```

**Аналіз:**

- Тип з'єднання: TCP.
- Порт: 80.
- Результат: [з'єднання встановлено / не встановлено].

**Пояснення:**

Команда `nc -vz` перевіряє можливість встановлення TCP-з'єднання з віддаленим сервером. Порт 80 зазвичай використовується для HTTP. Успішне виконання означає, що TCP-з'єднання з відповідним портом вдалося встановити.

### Завдання 4. Порівняння TCP та UDP (3 бали)

**Команда 1 — UDP:**

`nc -u -vz -w 3 8.8.8.8 53`

**Результат:**

```text
[Вставити результат UDP-перевірки]
```

**Команда 2 — TCP:**

`nc -vz -w 3 8.8.8.8 53`

**Результат:**

```text
[Вставити результат TCP-перевірки]
```

**Порівняння:**

TCP — протокол із встановленням з'єднання. Перед передаванням даних він виконує процедуру встановлення з'єднання, а також забезпечує підтвердження доставки та впорядкування даних.

UDP — протокол без встановлення з'єднання. Він не гарантує доставку пакетів або отримання відповіді.

Під час перевірки TCP можна визначити, чи вдалося встановити з'єднання. Для UDP повідомлення про успіх від `nc` не обов'язково підтверджує, що віддалений DNS-сервер отримав пакет або відповів на нього.

### Завдання 5. DNS-резолвінг (3 бали)

**Команда:**

`nslookup github.com`

**Результат виконання:**

```text
[Вставити результат команди nslookup github.com]
```

**Визначені параметри:**

- Домен: `github.com`.
- IP-адреса домену: [вставити IP].
- DNS-сервер: [вставити адресу DNS-сервера].

**Пояснення:**

DNS (Domain Name System) — система, яка перетворює доменні імена на IP-адреси. Команда `nslookup` дозволяє дізнатися IP-адресу домену та визначити DNS-сервер, який обробив запит. Завдяки DNS користувачам не потрібно запам'ятовувати числові IP-адреси сайтів.
